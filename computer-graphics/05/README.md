# Занятие 5. Заполнение областей и многоугольников

## 1. Как запустить
Открыть страницу на GitHub Pages. Выбрать полигон, нажать "Построить контур".
Для Flood Fill кликнуть по Canvas внутри области и нажать "Flood Fill".
Для Scanline — нажать "Scanline Fill".

## 2. Как задаётся многоугольник
Массивом вершин `[{x, y}, ...]` в логических координатах. Вершины
замыкаются автоматически (последняя соединяется с первой). Контур
рисуется алгоритмом ЦДА в логический растр.

## 3. Как хранится логический растр
Двумерный массив `baseGrid[y][x]` размером 40×30. Значения:
- `0` — пусто;
- `1` — граница;
- `2` — заливка (возвращается функциями `floodFill` и `scanlineFill` как массив пикселей).

## 4. Какой вариант связности используется
4-связность: соседи `(x±1, y)` и `(x, y±1)`. Диагонали не используются.

## 5. Правило обработки вершин в scanline
`min(y1, y2) <= y < max(y1, y2)`. Нижнюю границу включаем, верхнюю нет.
Так вершина, общая для двух рёбер, считается ровно один раз.
Горизонтальные рёбра (`y1 === y2`) пропускаются.

## 6. Результаты обязательных тестов

В ходе работы были проверены следующие фигуры и ситуации:

- **Прямоугольник, треугольник, выпуклый пятиугольник, невыпуклый многоугольник:** При использовании обоих алгоритмов количество закрашенных пикселей полностью совпало (273, 295, 392 и 378 пикселей соответственно). Визуально заливки идентичны.
- **Горизонтальное ребро:** При проверке прямоугольника (`y = 8`) и невыпуклого многоугольника (`y = 6`) алгоритм Scanline корректно игнорирует горизонтальные линии при поиске пересечений. Вывод программы: `Пересечения X: 8.00, 30.00` и `Интервалы: 8..30`. Ошибок деления на ноль нет.
- **Сканирующая строка проходит через вершину:** Для треугольника на строке `y = 4` алгоритм нашел ровно два пересечения (`20.00, 20.00`), а не четыре. Правило `yMin <= y < yMax` работает корректно и предотвращает двойной подсчет вершины.
- **Flood Fill со стартом внутри:** Закрашивает всю внутреннюю область, не задевая контур.
- **Flood Fill со стартом снаружи:** Закрашивает всю внешнюю область вокруг фигуры, не задевая контур.
- **Незамкнутый контур:** 
    *   *Flood Fill:* закрасил всё внешнее пространство (1163 пикселя), так как граница не замкнута и алгоритм "утек" наружу.
    *   *Scanline Fill:* закрасил 137 пикселей, словно мысленно проведя невидимую гипотенузу. Это доказывает, что Scanline работает с математическими координатами вершин, а не с нарисованными пикселями.

При сравнении на пятиугольнике расхождений нет (`Только у flood: 0`, `Только у scanline: 0`).

Было проведено две серии по 5 прогонов для каждого алгоритма:
- **Серия 1:** Flood Fill: среднее `0.20 мс` (разброс `0.00–1.00`), Scanline: `0.00 мс`.
- **Серия 2:** Оба алгоритма показали `0.00 мс`.

**Вывод по скорости:** Время выполнения настолько мало, что современные браузеры (движок V8) округляют его до нуля. Чтобы увидеть реальную разницу в скорости, нужны сетки размером 1000x1000 или тысячи повторных запусков. Однако алгоритмически Scanline быстрее, так как не использует стек и массивы для обхода соседей.

## Выводы

1.  **Когда нужен seed (стартовая точка):** Seed нужен только для **Flood Fill**. Он определяет, с какого пикселя начинать «расползание» по области. Scanline не нуждается в seed, так как строит заливку на основе математических вершин многоугольника.
2.  **Какой метод использует геометрию многоугольника:** **Scanline Fill**. Он находит пересечения рёбер с горизонтальными линиями и вычисляет интервалы по формуле. Flood Fill геометрию не знает — он просто ищет соседние пиксели, пока не упрется в контур.
3.  **Что произойдёт при разрыве контура:** 
    - *Flood Fill:* произойдет "утечка" — заливка выйдет за пределы фигуры и закрасит всё окружающее пространство (до краев растра), так как контур перестанет быть препятствием.
    - *Scanline Fill:* продолжит работать так, будто контур замкнут, так как он опирается на список вершин и по умолчанию соединяет последнюю вершину с первой.
4.  **Почему результаты на границе могут зависеть от правил округления:** Пересечения сканирующей строки с рёбрами имеют вещественные координаты (например, `5.3`). Для отрисовки используется `ceil()` и `floor()` для поиска ближайших целых пикселей. Из-за этого на краях фигуры Scanline может оставить незакрашенной тонкую полоску в 1 пиксель, которую Flood Fill закрасил бы (так как он просто проверяет соседей).
