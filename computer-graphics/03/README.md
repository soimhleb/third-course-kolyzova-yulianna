# Занятие 3. Растеризация окружности: алгоритм средней точки

1. **Как используется симметрия окружности?**
   Из одной вычисленной точки `(x, y)` получаются сразу восемь через
   отражения по осям и диагоналям. Функция `plot8` добавляет к ним
   смещение центра `(cx, cy)`. Считаем одну восьмую - рисуем всю
   окружность.

2. **Почему достаточно строить одну восьмую?**
   Окружность симметрична относительно обеих осей и диагоналей.
   Достаточно дуги от `(0, r)` до `x = y` (45°). Остальное -
   отражения уже построенных точек, без новых вычислений.

3. **Что означает переменная `d`?**
   Решающая величина для выбора следующего пикселя. Её знак показывает,
   где средняя точка между кандидатами E и SE относительно окружности:
   - `d < 0` - внутри, берём E (y не меняем);
   - `d >= 0` - снаружи или на границе, берём SE (y уменьшаем).

4. **Когда уменьшается `y`?**
   При `d >= 0` - окружность уже достаточно наклонилась, следующий
   пиксель должен быть справа-снизу: SE `(x + 1, y - 1)`.

5. **Почему цикл заканчивается при `x > y`?**
   Строим сектор до направления 45°. На границе `x === y`. Дальше
   симметрия даёт уже построенные точки - продолжать не нужно.

6. **Совпали ли пиксели midpoint и формулы?**
   Прогнаны радиусы 1, 2, 3, 4, 5, 10, 20, 50, 100.
   
   Совпали на 1, 2, 3, 5, 10, 20, 50, 100.
   
   Отличались только на r = 4: midpoint даёт 4 базовые точки,
   формула - 3. Лишняя точка у midpoint - (3, 3).
   
   Причина в разных критериях остановки:
   midpoint идёт `while (x <= y)` и захватывает точку на диагонали,
   где x = y = 3. Формула останавливается на
   `xMax = floor(r / √2) = floor(2.83) = 2`, поэтому точку (3, 3)
   не проверяет.

7. **Что показал замер времени?**
   Сделаны три прогона (5 замеров по 1000 окружностей в каждом):

   | Прогон | Midpoint (среднее) | Формула (среднее) |
   |---|---|---|
   | 1 | 1.40 мс | 0.40 мс |
   | 2 | 1.80 мс | 1.80 мс |
   | 3 | 2.20 мс | 1.40 мс |

   Результат неустойчивый: в одном прогоне быстрее формула, в другом -
   одинаково. Разброс между прогонами (до 1.4 мс) больше, чем средняя
   разница между алгоритмами (< 0.5 мс).

   Причина: радиусы 5–100 и 1000 итераций - слишком маленькая нагрузка,
   чтобы разница в стоимости `Math.sqrt` и целочисленных операций
   проявилась. Накладные расходы на вызов функции и работу JIT
   сравнялись с самой арифметикой.

   Вывод: по трём прогонам нельзя утверждать, что один алгоритм быстрее
   другого. Чтобы увидеть реальную разницу, нужно увеличить нагрузку
   (например, r = 1000, N = 100 000) или замерять на большем количестве
   радиусов.
