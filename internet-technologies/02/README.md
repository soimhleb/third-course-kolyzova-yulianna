# Занятие 2. Анализатор чисел

1. **Где хранятся исходные данные?**
   В одном массиве `values` в файле `app.js`.

2. **Почему показатели лучше вычислять из массива, а не хранить отдельно?**
   Если хранить сумму, среднее, min и max отдельными переменными, их придётся
   синхронизировать с массивом при каждом добавлении и удалении. Легко
   забыть обновить одно из них. Вычисление из массива
   всегда даёт актуальный результат и не требует ручной синхронизации.

3. **Что возвращает `getStatistics()`?**
   Объект вида `{ count, sum, min, max, average }`.

4. **Как программа обрабатывает пустой массив?**
   `getStatistics()` возвращает `null` для min, max и average. В `render()`
   эти `null` заменяются на «—», чтобы пользователь не видел `NaN` или
   `Infinity`. Количество и сумма равны `0`.

5. **Какое место было сложнее всего отладить?**
   Ветка с сообщением «Это не число» в обработчике кнопки «Добавить»
   сначала не срабатывала: при вводе букв появлялось «Введите число».
   Оказалось, что поле `type="number"` само отфильтровывает буквы, и в
   `input.value` попадает пустая строка, а не `'abc'`. Поэтому первая
   проверка `raw === ''` срабатывает раньше, а вторая до неё просто не
   доходит. Проверку `Number.isFinite(num)` я оставила на
   случай, если поле станет `type="text"` или значение придёт другим
   путём.
