# Занятие 6. REST API с SQLite

## Установка и запуск
1. Установите зависимости: `npm install`
2. Запустите сервер: `npm start`
Сервер доступен по адресу: `http://localhost:3000`

## Схема таблицы
Данные хранятся в базе `data.db` в таблице `books`:
* `id` — INTEGER PRIMARY KEY AUTOINCREMENT
* `title` — TEXT NOT NULL
* `author` — TEXT NOT NULL
* `available` — INTEGER NOT NULL DEFAULT 1 (хранится как 0 или 1)

## Список маршрутов и SQL
| Метод | URL | SQL | Успешный код | Ошибки |
| :--- | :--- | :--- | :--- | :--- |
| GET | `/api/books` | `SELECT` | 200 | — |
| GET | `/api/books/:id` | `SELECT` | 200 | 404 |
| POST | `/api/books` | `INSERT` | 201 | 400 |
| PATCH | `/api/books/:id` | `UPDATE` | 200 | 400, 404 |
| DELETE | `/api/books/:id` | `DELETE` | 204 | 404 |

## Примеры POST и PATCH
**Пример POST-запроса (создание книги):**
Отправляется на `POST /api/books`.
```json
{
  "title": "Dune",
  "author": "Frank Herbert"
}
```
**Пример PATCH-запроса (частичное обновление):**
Отправляется на `PATCH /api/books/1`. Можно передать только те поля, которые нужно изменить.
```json
{
  "available": false
}
```
*Сервер обновит только статус доступности, не трогая название и автора. Вернется обновленный объект с кодом 200.*

## Query-параметры
В API реализована фильтрация через параметры в URL. Оба фильтра выполняются на стороне базы данных через SQL-запросы:
- `?author=` — поиск по автору. В SQL используется оператор `LIKE` для поиска совпадений по подстроке (без учета точного регистра, если в SQLite настроено по умолчанию).
Пример: `GET /api/books?author=Orwell`
- `?available=` — фильтрация по доступности (`true` или `false`). В SQL используется точное сравнение `=`.
Пример: `GET /api/books?available=false`
- Параметры можно комбинировать: `GET /api/books?author=Tolkien&available=true`.

## Правила валидации
Для защиты данных настроены следующие проверки на сервере:
- Обязательные поля: При создании (`POST`) и обновлении (`PATCH`) поля `title` и `author` обязательны. Если хотя бы одно из них отсутствует или состоит только из пробелов (благодаря `.trim()`), сервер вернет ошибку с кодом `400 Bad Request`.
- Типы данных: Поле `available` приводится к логическому типу. В базе SQLite оно хранится как `1` (true) или `0` (false).
- Параметризованные SQL-запросы: Все данные от клиента (ID, поля книг, query-параметры) передаются в SQL через плейсхолдеры `?` (например, `WHERE id = ?`). Это полностью исключает SQL-инъекции.
