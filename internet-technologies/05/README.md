# Занятие 5. Собственный REST API

## Установка зависимостей
Для установки всех необходимых библиотек (Express) выполните в терминале команду:
```bash
npm install
```

## Запуск
Запустить сервер можно командой:
```bash
npm start
```
После запуска сервер будет доступен по адресу: http://localhost:3000

## Выбранная сущность
В качестве сущности выбраны **Книги (books)**. Данные хранятся в памяти сервера в виде массива объектов, содержащих поля:
- `id` (уникальный идентификатор)
- `title` (название книги)
- `author` (автор)
- `year` (год издания)
- `available` (доступна ли книга)

## Список маршрутов
В API реализованы следующие эндпоинты:
- `GET /api/books` — получить список всех книг.
- `GET /api/books/:id` — получить одну книгу по её ID.
- `POST /api/books` — создать новую книгу.
- `GET /api/info` — служебный маршрут для получения информации о сервере и количестве книг.
- Любой другой маршрут — возвращает ошибку 404 (Route not found).

## Примеры query
Query-параметры используются для фильтрации коллекции.
В реализации поддерживаются два параметра:
- `author` — фильтрует книги по автору (без учета регистра).
- `available` — фильтрует по доступности (true или false).

Примеры запросов:
- `http://localhost:3000/api/books?author=Tolkien` — вернет только книги Толкина.
- `http://localhost:3000/api/books?available=true` — вернет только доступные книги.
- `http://localhost:3000/api/books?author=Tolkien&available=true` — можно комбинировать параметры.

## Примеры корректного и ошибочного запроса
Для создания книги используется метод POST.

**Пример корректного запроса (вернет статус 201 Created):**
``` bash
{
  "title": "Dune",
  "author": "Frank Herbert",
  "year": 1965
}
```
*Сервер сгенерирует ID и вернет созданный объект.*

**Пример ошибочного запроса (вернет статус 400 Bad Request):**
``` bash
{
  "author": "Frank Herbert"
}
```
*В запросе отсутствует обязательное поле title. Сервер вернет ошибку:* `{"error": "title and author are required"}`.
